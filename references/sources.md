# Sources

Where the rules come from, one line per source, grouped by the reference that uses it. Only primary sources: manuals, release notes and standards

## The shape

- [Bash manual, The Set Builtin](https://www.gnu.org/software/bash/manual/html_node/The-Set-Builtin.html) — `-e`, `-u`, `-o pipefail`, and the list of contexts `-e` is not in effect in, which is why a failure inside `if`, `&&`, `||` or a `!` is not a failure at all; [Pipelines](https://www.gnu.org/software/bash/manual/html_node/Pipelines.html) — a pipeline's status is its last command's unless `pipefail` is on; [Bash Variables](https://www.gnu.org/software/bash/manual/html_node/Bash-Variables.html) — `PIPESTATUS` is rewritten by the next simple command, so the whole array is copied in one; [sysexits(3)](https://man.freebsd.org/cgi/man.cgi?query=sysexits&sektion=3) — `EX_USAGE` is 64, "the command was used incorrectly, e.g., with the wrong number of arguments, a bad flag, a bad syntax in a parameter, or whatever", and `EX_SOFTWARE` is 70, the 64 to 89 band a harness takes when its own 1 belongs to the command it runs

The ruling "2 for a usage error everywhere" is a survey, not a preference — what the tools on this machine answer to an unknown flag `--bogus`, measured on 2026-09-11:

| Exit | Tools that answer a usage error with it |
|---|---|
| 2 | bash, ls, grep, curl, jq, rg, shfmt, Python argparse |
| 1 | find, sed, rsync, nix, gh, zsh |
| other | 3 shellcheck, 9 node, 64 GNU tar (`EX_USAGE` from sysexits), 125 docker, 129 git, 255 ssh |

2 is the only value with a plurality behind it and the only one shared by the shell itself and by the tools a script is written next to; 1 is taken by "the thing you asked about is wrong", which a usage error is not

## The help

- [Greg's Wiki, BashFAQ/035](https://mywiki.wooledge.org/BashFAQ/035) — "if you want to handle GNU-style --long-options or Tcl-style -longopts, a manual loop is your only choice. getopts does not support these", and `getopts` buys only concatenated single letters in exchange, which is why the hand-rolled `while (($#))` loop wins the moment a help advertises a long flag

## Portability

- [Bash NEWS](https://tiswww.case.edu/php/chet/bash/NEWS) — the floor under every row of the construct table, each one confirmed against the NEWS text: 4.0 brought `mapfile`/`readarray`, associative arrays, the `^^`/`,,` case modifications, `|&` as "a synonym for `2>&1 |`" and the `;;&` case terminator; 4.1 the `{var}` redirection that assigns the descriptor to a variable; 4.2 the `-v` unary operator and negative lengths in `${var:offset:length}`; 4.3 namerefs and `wait -n`; 4.4 the `${parameter@spec}` transformations; 5.2 the `patsub_replacement` option under which "a `&` in the replacement string of the pattern substitution expansion is replaced by the portion of the string that matched the pattern"; [Bash manual, Shell Parameter Expansion](https://www.gnu.org/software/bash/manual/html_node/Shell-Parameter-Expansion.html) — the substitution, case-modification and transformation forms whose floors the NEWS file dates, and the replacement word whose quotes bash 3.2 keeps literally
- The macOS man pages, served by man.freebsd.org under a macOS manpath: [sed](https://man.freebsd.org/cgi/man.cgi?query=sed&sektion=1&manpath=macOS+14.8.5) — `-i` takes an *extension* argument; [grep](https://man.freebsd.org/cgi/man.cgi?query=grep&sektion=1&manpath=macOS+14.8.5) — `-E`, `-F` and `-G` and no `-P` anywhere on the page; [readlink](https://man.freebsd.org/cgi/man.cgi?query=readlink&sektion=1&manpath=macOS+14.8.5); [date](https://man.freebsd.org/cgi/man.cgi?query=date&sektion=1&manpath=macOS+14.8.5) — `-v`, `-j` and `-f`, and no GNU `-d`; [mktemp](https://man.freebsd.org/cgi/man.cgi?query=mktemp&sektion=1&manpath=macOS+14.8.5) — "If no arguments are passed or if only the **-d** flag is passed **mktemp** behaves as if **-t** **tmp** was supplied". The manpath has to be one the site currently offers, because an unknown one can answer 200 while silently serving the FreeBSD page instead
- [coreutils NEWS](https://git.savannah.gnu.org/cgit/coreutils.git/tree/NEWS) — release 9.8 (2025-09-22): "fold now supports multi-byte characters, honoring their column width. Also the --characters (-c) option was added", so the same `fold` call wraps differently on either side of that release; [GNU grep NEWS](https://git.savannah.gnu.org/cgit/grep.git/tree/NEWS) — release 3.12 (2025-04-10) removed `--unix-byte-offsets` (`-u`) and fixed the 100000-entry directory that failed with exit 2. The project's own NEWS file is the source in both cases, never savannah.gnu.org/news, which serves scraper garbage under that name
- [Docker Hub, the `bash` image](https://hub.docker.com/_/bash) — the `3.2` tag, 3.2.57, which every 3.2 measurement in the references was taken under

## Pitfalls

- [POSIX.1-2024, Shell Command Language 2.12 Signals and Error Handling](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_12) — "If job control is disabled (see the description of set -m) when the shell executes an asynchronous AND-OR list, the commands in the list shall inherit from the shell a signal action of ignored (SIG_IGN) for the SIGINT and SIGQUIT signals", which no `trap` in the child can undo; [Bash manual, Job Control Builtins](https://www.gnu.org/software/bash/manual/html_node/Job-Control-Builtins.html) — the builtins `set -m` turns on, the switch that decides whether a background job is its own process group
- [Greg's Wiki, SignalTrap](https://mywiki.wooledge.org/SignalTrap) — "a process that exits in response to SIGINT should kill itself with SIGINT rather than simply exiting, to avoid causing problems for its caller", spelled `trap 'rm -f "$tempfile"; trap - INT; kill -s INT "$$"' INT`; [BashPitfalls](https://mywiki.wooledge.org/BashPitfalls) — the catalogue of word-splitting, globbing and array mistakes the rules here are the local spelling of, "it is not safe to populate an array with a raw $(…)" among them
- [pgrep(1)](https://man7.org/linux/man-pages/man1/pgrep.1.html) — "the process name used for matching is limited to the 15 characters present in the output of /proc/pid/stat", with `-f` against `/proc/pid/cmdline` named on the page as the way out; [xargs(1)](https://man7.org/linux/man-pages/man1/xargs.1.html) — it "executes the command (default is echo)" over items "delimited by blanks (which can be protected with double or single quotes or a backslash)", the two reasons `| xargs` is not a whitespace trim
- [POSIX.1-2024, Shell Command Language 2.6.5 Field Splitting](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html#tag_19_06_05) — "the term 'IFS white space' is used to mean any of the white-space bytes <space>, <tab>, or <newline>", and only an IFS character that is not IFS white space delimits an empty field, which is why a tab-separated `read` folds; [POSIX.1-2024, awk](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/awk.html) — a `-v` value "shall be interpreted as if they appeared in the awk program preceded and followed by a double-quote ('"') character, as a STRING token", a backslash before a character the escape table does not list is "Undefined", and each `ENVIRON` element is "a string consisting of the value of that variable"

## The harness

- [Zsh manual, Expansion](https://zsh.sourceforge.io/Doc/Release/Expansion.html) — 14.7.3 `=` expansion, "if a word begins with an unquoted `=` and the EQUALS option is set, the remainder of the word is taken as the name of a command", so a bare `=cmd` in an ad-hoc line is not the literal text it looks like; and 14.1.4 Modifiers, where `:h`, `:t`, `:r` and `:e` after an expansion are history-style modifiers that silently eat text; and Filename Generation, "if no matching pattern is found, the shell gives an error message, unless the NULL_GLOB option is set, in which case the word is deleted; or unless the NOMATCH option is unset, in which case the word is left unchanged"
- [Zsh manual, Options](https://zsh.sourceforge.io/Doc/Release/Options.html) — `NOMATCH`, set in zsh's own emulation: "if a pattern for filename generation has no matches, print an error, instead of leaving it unchanged in the argument list", which is why a URL with a query string or an unquoted `-name *.sh` fails in the agent's shell and passes in bash
- [Zsh manual, Parameters](https://zsh.sourceforge.io/Doc/Release/Parameters.html) — 15.2.1 Array Subscripts, "the elements are numbered beginning with 1, unless the KSH_ARRAYS option is set in which case they are numbered from zero", and 15.5, where `pipestatus` is zsh's spelling of `PIPESTATUS`, indexed from 1, and `status` is zsh's own `$?` and therefore a name no script may assign to
- [Claude Code, tools reference](https://code.claude.com/docs/en/tools-reference) — "at session start, Claude Code sources `~/.zshrc`, `~/.bashrc`, or `~/.profile` depending on your shell, captures the resulting aliases, functions, and shell options, and applies them to every Bash command". That is as close as the documentation comes: it names the startup files and says "depending on your shell" without ever naming the interpreter, so which shell an ad-hoc command actually runs in is settled by the measurement at the top of [harness.md](harness.md) rather than by the page

## Completions

- [Bash manual, Programmable Completion Builtins](https://www.gnu.org/software/bash/manual/html_node/Programmable-Completion-Builtins.html) — `complete`, `compgen` and `compopt`, and the `COMPREPLY`, `COMP_WORDS`, `COMP_CWORD` contract a completion function is called under; `compopt` is the one of the three that arrived only in bash 4.0 — "there is a new `compopt' builtin that allows completion functions to modify completion options" in the NEWS above — which is why the call is guarded
- [Zsh manual, Completion System](https://zsh.sourceforge.io/Doc/Release/Completion-System.html) — 20.2.2 Autoloaded files: a file "whose first line does not start with one of these tags" is not part of the completion system at all, so `#compdef <cmd>` is the binding and not a comment, the function has to sit "in a directory mentioned in the `fpath` parameter", and `compdef` is what associates one by hand for a file that is sourced from a checkout instead
- [bash-completion, README](https://github.com/scop/bash-completion) — "completions are automatically loaded on demand based on invoked commands' names, so be sure to name your completion file accordingly", the directory being `pkg-config --variable=completionsdir bash-completion`, and the `.bash` suffix taking load-order precedence over the bare name

## Lint

- [ShellCheck SC2251](https://www.shellcheck.net/wiki/SC2251) — "this `!` is not on a condition and skips errexit"; [SC2016](https://www.shellcheck.net/wiki/SC2016) — "expressions don't expand in single quotes, use double quotes for that", the finding a script that writes shell keeps hitting on purpose; [SC2100](https://www.shellcheck.net/wiki/SC2100) — "use `$((..))` for arithmetics", because `i=i+2` assigns the string; [SC2207](https://www.shellcheck.net/wiki/SC2207) — "prefer `mapfile` or `read -a` to split command output (or quote to avoid splitting)", whose first suggestion this family declines on the 3.2 floor and answers with the read loop
- [shfmt, in mvdan/sh](https://github.com/mvdan/sh) — the formatter, whose opinion is versioned, so a bump and the reformat it causes are one commit. Its flags live in [shfmt.1.scd](https://github.com/mvdan/sh/blob/master/cmd/shfmt/shfmt.1.scd) rather than in the README: `-i` is "0 for tabs (default), >0 for number of spaces", `-ci` is "switch cases will be indented", and `-d` is "error with a diff when the formatting differs"
